# 处理管线优化方案

## 设计原则

1. **同设备连续处理** — 减少 CPU↔GPU 传输次数
2. **优先 GPU 处理** — 将适合的算法迁移到 WebGPU Shader
3. **智能格式转换** — 按需转换，而非每步都转换

---

## 核心设计：延迟转换策略

### 数据格式类型

```typescript
type 管线数据格式 = 
    | { 类型: 'GPUBuffer'; buffer: GPUBuffer; width: number; height: number }
    | { 类型: 'GPUTexture'; texture: GPUTexture; width: number; height: number }
    | { 类型: 'ImageData'; imageData: ImageData }
    | { 类型: 'Canvas'; canvas: OffscreenCanvas }
```

### 节点能力声明

每个处理节点声明自己能接受和产出的格式：

```typescript
interface 处理节点 {
    名称: string
    
    /** 条件判断：是否需要执行 */
    guard: (options: 处理选项) => boolean
    
    /** 声明：可接受的输入格式 (优先级从高到低) */
    可接受输入: 管线数据格式['类型'][]
    
    /** 声明：产出的输出格式 */
    输出格式: 管线数据格式['类型']
    
    /** 处理函数 */
    process: (input: 管线数据, context: 节点上下文) => Promise<管线数据>
}
```

## 管线调度器

### 调度逻辑

```
1. 收集所有需要执行的节点 (guard 返回 true)
2. 分析连续节点的格式兼容性
3. 合并同格式节点，减少转换次数
4. 只在格式不兼容时执行转换
```

### 调度算法

```typescript
function 规划执行顺序(启用的节点: 处理节点[], 初始格式: 格式类型): 执行计划 {
    const 执行计划: 执行步骤[] = []
    let 当前格式 = 初始格式
    
    for (const 节点 of 启用的节点) {
        // 检查是否需要格式转换
        if (!节点.可接受输入.includes(当前格式)) {
            // 需要转换：选择节点最优先的格式
            const 目标格式 = 节点.可接受输入[0]
            执行计划.push({ 类型: '转换', from: 当前格式, to: 目标格式 })
            当前格式 = 目标格式
        }
        
        // 添加处理步骤
        执行计划.push({ 类型: '处理', 节点 })
        当前格式 = 节点.输出格式
    }
    
    return 执行计划
}
```

### 优化：合并连续 CPU 节点

```
原始顺序:
  GPU → [曝光(CPU)] → [去雾(CPU)] → [清晰度(CPU)] → GPU

检测到连续 CPU 节点，合并传输:
  GPU → CPU → [曝光 → 去雾 → 清晰度] → GPU

传输次数: 6次 → 2次
```

实现方式：

```typescript
function 优化执行计划(计划: 执行步骤[]): 执行步骤[] {
    const 优化后: 执行步骤[] = []
    let CPU批处理: 处理节点[] = []
    
    for (const 步骤 of 计划) {
        if (步骤.类型 === '处理' && 步骤.节点.输出格式 === 'ImageData') {
            // 累积 CPU 处理节点
            CPU批处理.push(步骤.节点)
        } else {
            // 遇到非 CPU 节点，先执行累积的 CPU 批处理
            if (CPU批处理.length > 0) {
                优化后.push({ 类型: 'CPU批处理', 节点列表: CPU批处理 })
                CPU批处理 = []
            }
            优化后.push(步骤)
        }
    }
    
    // 处理末尾的 CPU 批处理
    if (CPU批处理.length > 0) {
        优化后.push({ 类型: 'CPU批处理', 节点列表: CPU批处理 })
    }
    
    return 优化后
}
```

## 格式转换器

### 转换矩阵

| From \ To | GPUBuffer | GPUTexture | ImageData | Canvas |
|-----------|:---------:|:----------:|:---------:|:------:|
| GPUBuffer | - | ✅ 快 | ⚠️ 慢 | ⚠️ 慢 |
| GPUTexture | ✅ 快 | - | ⚠️ 慢 | ✅ 快* |
| ImageData | ✅ 快 | ✅ 快 | - | ✅ 快 |
| Canvas | ⚠️ 慢 | ✅ 快 | ✅ 快 | - |

*注: GPUTexture → Canvas 可通过 WebGPU Canvas 互操作实现零拷贝

### 转换函数注册

```typescript
const 转换器注册表 = new Map<string, 转换函数>()

转换器注册表.set('GPUBuffer→ImageData', gpuBufferToImageData)
转换器注册表.set('ImageData→GPUBuffer', imageDataToGPUBuffer)
转换器注册表.set('GPUTexture→Canvas', async (texture, ctx) => {
    // 使用 WebGPU Canvas 互操作，可能实现零拷贝
    ctx.canvas.getContext('webgpu')?.getCurrentTexture()
    // ...
})
```

## 节点迁移计划

### 可快速 GPU 化的节点

| 节点 | 当前实现 | 迁移难度 | 收益 |
|------|:--------:|:--------:|:----:|
| 曝光调整 | CPU | ⭐ 简单 | 高 |
| 亮度调整 | CPU | ⭐ 简单 | 高 |
| 对比度 | CPU | ⭐ 简单 | 高 |
| Gamma | CPU | ⭐ 简单 | 高 |

**曝光 Shader 示例**:
```wgsl
@compute @workgroup_size(8, 8)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
    let idx = id.y * width + id.x;
    let pixel = input[idx];
    
    // 曝光调整: RGB * exposure
    let adjusted = vec4<f32>(
        pixel.rgb * exposure,
        pixel.a
    );
    
    output[idx] = clamp(adjusted, vec4(0.0), vec4(1.0));
}
```

### 需要更多工作的节点

| 节点 | 当前实现 | 迁移难度 | 说明 |
|------|:--------:|:--------:|------|
| 清晰度 | CPU | ⭐⭐ 中等 | 需要卷积，多 pass |
| 去雾 | CPU | ⭐⭐⭐ 较难 | 暗通道先验算法复杂 |
| 无缝化 | CPU | ⭐⭐⭐⭐ 难 | 边缘混合算法特殊 |

### 短期 vs 长期策略

**短期 (合并传输)**:
- 不改变节点实现
- 只优化调度器，合并连续 CPU 节点
- 预计收益: 传输次数从 13 减少到 ~5

**中期 (GPU 化简单节点)**:
- 曝光、亮度迁移到 GPU Shader
- 预计收益: 进一步减少 2-4 次传输

**长期 (全 GPU 管线)**:
- 所有节点都有 GPU 实现
- 只在输入/输出时传输
- 预计收益: 传输次数降到 2
