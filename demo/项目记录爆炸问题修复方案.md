# 画布模式管理方案

## 问题总结

当前架构中存在两个相互关联的问题：

1. **项目记录爆炸**：调整程序化纹理参数时，每次修改都会创建新项目
2. **画布不实时响应**：程序化纹理调整时，用户看不到实时预览效果

**根本原因**：当前架构将所有图像操作都绑定到 `rawOriginalImage` 和项目系统，没有区分"临时预览"和"持久化结果"两种不同的渲染场景。

---

## 设计目标

设计一个统一的**画布模式管理器 (Canvas Mode Manager)**，满足以下需求：

1. 支持多种渲染模式（项目预览、程序化纹理编辑、绘制模式等）
2. 模式切换时自动更换渲染管线，主画布显示对应模式的输出
3. 临时模式不污染项目数据，只在用户确认时才持久化
4. 易于扩展，未来添加新模式（如绘制模式、AI 生成模式）只需注册即可

---

## 核心概念

### 画布模式 (Canvas Mode)

画布模式是一个渲染上下文，定义了：

| 属性 | 说明 |
|------|------|
| `id` | 模式唯一标识，如 `'project'`, `'procedural'`, `'paint'` |
| `displayName` | 显示名称 |
| `source` | 输入源（项目原图 / 程序化生成 / 上一模式输出） |
| `pipeline` | 处理管线 |
| `output` | 输出目标（主画布 ref） |
| `persistStrategy` | 持久化策略（无 / 确认时 / 自动） |

### 模式类型

```
┌─────────────────────────────────────────────────────────────┐
│                     Canvas Mode Manager                      │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │   Project    │  │  Procedural  │  │    Paint     │  ...  │
│  │    Mode      │  │    Mode      │  │    Mode      │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
│        │                 │                 │                 │
│        ▼                 ▼                 ▼                 │
│  ┌────────────────────────────────────────────────────┐     │
│  │              Active Canvas Output                   │     │
│  │            (Viewer Component Display)               │     │
│  └────────────────────────────────────────────────────┘     │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 模式定义

### 1. 项目模式 (Project Mode) - 默认

```typescript
{
    id: 'project',
    displayName: '项目预览',
    source: () => projectState.activeOriginalDataUrl,
    pipeline: standardProcessingPipeline,  // LUT、HSL、曝光等
    persistStrategy: 'auto',  // 参数变更自动保存到项目
}
```

**特点**：
- 这是当前的默认模式
- 图像来源于项目系统
- 参数变更自动持久化到 IndexedDB

### 2. 程序化纹理模式 (Procedural Mode)

```typescript
{
    id: 'procedural', 
    displayName: '程序化纹理',
    source: () => proceduralGenerator.output,  // 临时生成的纹理
    pipeline: proceduralPreviewPipeline,
    persistStrategy: 'confirm',  // 仅确认时保存
}
```

**特点**：
- 图像来源于程序化纹理生成器（噪声、分形等）
- 实时响应参数调整，直接更新画布
- **不会创建项目**，直到用户点击"保存为项目"
- 切换回项目模式时丢弃临时数据

### 3. 绘制模式 (Paint Mode) - 未来

```typescript
{
    id: 'paint',
    displayName: '绘制',
    source: () => currentLayer.composite,
    pipeline: paintPreviewPipeline,
    persistStrategy: 'confirm',
}
```

## 模式切换流程

```
用户点击"程序化纹理"标签
        │
        ▼
┌───────────────────────────────┐
│ canvasModeManager.switch('procedural')
└───────────────────────────────┘
        │
        ├─→ 1. 保存当前模式状态（如有需要）
        │
        ├─→ 2. 切断当前模式与主画布的连接
        │
        ├─→ 3. 初始化新模式的渲染管线
        │
        ├─→ 4. 将新模式输出连接到主画布
        │
        └─→ 5. 触发首次渲染

用户调整程序化纹理参数
        │
        ▼
┌───────────────────────────────┐
│ proceduralMode.updateParams()
│     → 重新生成纹理
│     → 更新主画布显示
│     → ❌ 不触发 createProject
└───────────────────────────────┘

用户点击"保存为项目"
        │
        ▼
┌───────────────────────────────┐
│ proceduralMode.persist()
│     → 将当前输出转为 Blob
│     → 调用 projectState.createProject()
│     → 自动切换回项目模式
└───────────────────────────────┘
```

## API 设计

### CanvasModeManager

```typescript
interface CanvasModeManager {
    /** 当前激活的模式 */
    readonly activeMode: Ref<CanvasMode>
    
    /** 所有已注册的模式 */
    readonly modes: Map<string, CanvasMode>
    
    /** 主画布输出 (Viewer 组件应 watch 这个) */
    readonly canvasOutput: Ref<CanvasOutput>
    
    /** 切换模式 */
    switchMode(modeId: string): Promise<void>
    
    /** 注册新模式 */
    registerMode(mode: CanvasModeDefinition): void
    
    /** 持久化当前模式结果 */
    persistCurrentMode(): Promise<ImageProject | null>
}

interface CanvasMode {
    id: string
    displayName: string
    
    /** 进入模式时调用 */
    onEnter(): Promise<void>
    
    /** 退出模式时调用 */
    onExit(): Promise<void>
    
    /** 获取当前输出 */
    getOutput(): CanvasOutput
    
    /** 是否有未保存的更改 */
    isDirty: Ref<boolean>
}

interface CanvasOutput {
    /** 显示用的 DataURL 或 ImageBitmap */
    displayImage: string | ImageBitmap | null
    
    /** 可选的叠加层（如网格、辅助线） */
    overlays?: OverlayLayer[]
}
```

### 使用示例

```typescript
// 在控制面板中
const { activeMode, switchMode, canvasOutput } = useCanvasModeManager()

// 切换到程序化纹理模式
async function handleProceduralClick() {
    await switchMode('procedural')
}

// 在 Viewer 组件中
watch(canvasOutput, (output) => {
    // 渲染到画布
    renderToCanvas(output.displayImage)
    renderOverlays(output.overlays)
})
```

## 与现有代码的集成

### 需要修改的关键点

1. **Viewer 组件**
   - 从 watch `processedImage` 改为 watch `canvasModeManager.canvasOutput`
   
2. **DesktopControls**
   - 各控制面板需要判断当前模式，决定是直接操作还是切换模式
   
3. **useTextureState**
   - 参数代理需要检查当前模式，只有在项目模式下才更新项目参数

4. **程序化纹理面板**
   - 不再直接操作 `rawOriginalImage`
   - 改为操作 `proceduralMode` 的内部状态
   - 提供"保存为项目"按钮

### 不需要修改的部分

- 项目存储系统 (IndexedDB)
- 批量导出逻辑
- LUT、HSL 等效果处理逻辑（作为管线的一部分被复用）

## 扩展性考虑

### 添加新模式的步骤

1. 创建模式定义文件，如 `canvasModes/paintMode.ts`
2. 实现 `CanvasMode` 接口
3. 在应用初始化时注册：`canvasModeManager.registerMode(paintMode)`
4. 在 UI 中添加切换入口

### 模式间数据传递

某些场景需要模式间传递数据，例如：
- 在程序化纹理上继续绘制
- 将绘制结果应用效果

可以通过 `CanvasOutput` 的可选属性支持：

```typescript
interface CanvasOutput {
    displayImage: string | ImageBitmap | null
    
    /** 允许其他模式使用此输出作为输入 */
    canBeSourceFor?: string[]  // ['paint', 'effects', ...]
}
```

## 总结

这个方案的核心思想是：

> **画布是一个统一的输出目标，不同模式轮流控制它的内容**

通过模式抽象，我们可以：
1. ✅ 解决项目记录爆炸问题（程序化模式不自动创建项目）
2. ✅ 解决画布不实时响应问题（程序化模式直接更新画布）
3. ✅ 为未来功能扩展铺路（绘制、AI 等模式只需注册即可）
4. ✅ 保持代码整洁（每个模式职责单一）
