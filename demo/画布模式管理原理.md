# 画布模式管理原理文档

## 概述

画布模式管理系统是一个统一的渲染上下文管理器，用于处理不同场景下的画布输出（项目预览、程序化纹理编辑等）。它解决了以下核心问题：

1. **项目记录爆炸**：程序化纹理调整时不再自动创建项目
2. **画布实时响应**：参数调整时主画布能够实时更新
3. **模式隔离**：不同模式的数据和行为相互独立
4. **效果调节器隔离**：程序化模式下自动禁用项目效果调节器，避免性能问题

## 核心概念

### 1. 画布模式 (Canvas Mode)

每个画布模式是一个独立的渲染上下文，定义了：

| 属性 | 说明 | 示例 |
|------|------|------|
| `id` | 模式唯一标识 | `'project'`, `'procedural'` |
| `displayName` | 显示名称 | `'项目预览'`, `'程序化纹理'` |
| `persistStrategy` | 持久化策略 | `'auto'`, `'confirm'`, `'none'` |
| `isDirty` | 是否有未保存的更改 | `Ref<boolean>` |
| `onEnter()` | 进入模式时的回调 | 初始化状态 |
| `onExit()` | 退出模式时的回调 | 清理临时数据 |
| `getOutput()` | 获取当前输出 | 返回 `CanvasOutput` |
| `persist()` | 持久化当前结果 | 保存为项目 |

### 2. 画布输出 (Canvas Output)

```typescript
interface CanvasOutput {
    /** 显示用的图像 */
    displayImage: string | ImageBitmap | null
    
    /** 可选的叠加层（如网格、辅助线） */
    overlays?: OverlayLayer[]
    
    /** 允许其他模式使用此输出作为输入 */
    canBeSourceFor?: string[]
    
    /** 元数据 */
    metadata?: {
        mode: string
        isDirty: boolean
        hasTexture?: boolean
        version?: number  // 用于响应式追踪
    }
}
```

## 响应式机制详解

### 问题背景

在实现程序化纹理模式时，遇到了一个关键的响应式追踪问题：

```typescript
// useCanvasModeManager.ts
const canvasOutput = computed<CanvasOutput>(() => {
    if (!activeMode.value) {
        return { ...DEFAULT_CANVAS_OUTPUT }
    }
    return activeMode.value.getOutput()  // ❌ 无法追踪内部状态变化
})
```

**问题**：
- `canvasOutput` 是 computed 属性
- 它依赖 `activeMode.value.getOutput()`
- 但 `getOutput()` 返回的是普通对象，内部状态变化时 Vue 无法检测

### 解决方案：版本号机制

#### 1. 添加响应式版本号

```typescript
// proceduralMode/index.ts
export function createProceduralMode(): ProceduralModeInstance {
    const isDirty = ref(false)
    const outputVersion = ref(0)  // ✅ 响应式版本号
    
    let currentTextureDataUrl: string | null = null
    
    return {
        id: CANVAS_MODE_IDS.PROCEDURAL,
        isDirty,
        outputVersion,  // ✅ 暴露给外部
        
        setCurrentTexture(dataUrl: string | null): void {
            currentTextureDataUrl = dataUrl
            isDirty.value = true
            outputVersion.value++  // ✅ 每次更新时递增
        },
        
        getOutput: createGetOutputMethod(getCurrentTexture, isDirty, outputVersion)
    }
}
```

#### 2. 在 getOutput 中访问版本号

```typescript
// proceduralMode/factory.utils.ts
function createGetOutputMethod(
    getCurrentTexture: () => string | null,
    isDirty: { value: boolean },
    outputVersion: { value: number }  // ✅ 接收版本号
): () => CanvasOutput {
    return (): CanvasOutput => {
        // ✅ 访问 outputVersion.value 建立响应式依赖
        const _version = outputVersion.value
        
        return {
            displayImage: getCurrentTexture(),
            overlays: [],
            metadata: {
                mode: CANVAS_MODE_IDS.PROCEDURAL,
                isDirty: isDirty.value,
                version: _version  // ✅ 包含在输出中
            }
        }
    }
}
```

#### 3. 响应式链路

```
用户调整参数
    ↓
setCurrentTexture(newDataUrl)
    ↓
outputVersion.value++  ← 触发响应式更新
    ↓
canvasOutput (computed) 重新计算
    ↓
activeMode.value.getOutput() 被调用
    ↓
访问 outputVersion.value  ← 建立依赖关系
    ↓
返回新的 CanvasOutput
    ↓
Viewer 组件自动更新
```

### 关键要点

1. **版本号必须是响应式的**：使用 `ref(0)` 而不是普通变量
2. **必须在 computed 中访问**：在 `getOutput()` 中访问 `outputVersion.value`
3. **每次状态变化都要递增**：确保 Vue 能检测到变化

## 模式实现指南

### 项目模式 (Project Mode)

**特点**：
- 默认模式，用于预览和编辑项目图像
- 图像来源于项目系统 (`useProjectState`)
- 参数变更自动持久化到 IndexedDB
- 持久化策略：`'auto'`

**实现文件**：

**核心逻辑**：
```typescript
export function createProjectMode(): CanvasMode {
    const { state: projectState } = useProjectState()
    
    return {
        id: CANVAS_MODE_IDS.PROJECT,
        displayName: MODE_DISPLAY_NAMES.PROJECT,
        persistStrategy: 'auto',
        
        getOutput(): CanvasOutput {
            return {
                displayImage: projectState.activeOriginalDataUrl.value,
                overlays: []
            }
        },
```

### 程序化纹理模式 (Procedural Mode)

**特点**：
- 用于实时预览和调整程序化纹理生成参数
- 图像来源于程序化纹理生成器
- 不会自动创建项目，只在用户确认时才持久化
- 持久化策略：`'confirm'`
- **使用版本号机制实现响应式更新**

**实现文件**：
- [`demo/src/composables/canvas-mode/modes/proceduralMode/index.ts`](demo/src/composables/canvas-mode/modes/proceduralMode/index.ts:1)

**核心逻辑**：
```typescript
export function createProceduralMode(): ProceduralModeInstance {
    const isDirty = ref(false)
    const outputVersion = ref(0)  // 响应式版本号
    let currentTextureDataUrl: string | null = null
    
    return {
        id: CANVAS_MODE_IDS.PROCEDURAL,
        displayName: MODE_DISPLAY_NAMES.PROCEDURAL,
```

```typescript
): Promise<void> {
```

## Viewer 组件集成

### 1. 画布模式感知的图像源

**实现位置**：[`demo/src/components/Viewer.ctx.ts`](demo/src/components/Viewer.ctx.ts:42)

```typescript
export function createViewerImageSource(
    fallbackOriginal: Ref<string | null>,
    fallbackProcessed: Ref<string | null>
): ViewerImageSource {
    const canvasModeManager = useCanvasModeManager()
    
    const originalImage = computed(() => {
        const currentMode = canvasModeManager.activeModeId.value
        
        // 程序化模式：使用画布输出
        if (currentMode === CANVAS_MODE_IDS.PROCEDURAL) {
            const output = canvasModeManager.canvasOutput.value
            return isString(output.displayImage) ? output.displayImage : null
        }
        
        // 项目模式：使用fallback原始图像
        return fallbackOriginal.value
    })
    
    const processedImage = computed(() => {
        const currentMode = canvasModeManager.activeModeId.value
        
        // 程序化模式：使用画布输出
        if (currentMode === CANVAS_MODE_IDS.PROCEDURAL) {
            const output = canvasModeManager.canvasOutput.value
            return isString(output.displayImage) ? output.displayImage : null
        }
        
        // 项目模式：使用fallback处理后图像
        return fallbackProcessed.value
    })
    
    return { originalImage, processedImage }
}
```

## 问题修复记录

### 问题 2.1: 程序化纹理调整时未自动禁用后续的效果调节器

#### 问题描述

**现象**：
- 用户在程序化纹理模式下调整参数时，仍然可以访问其他效果调节器面板（HSL、Exposure、Dehaze、Clarity、Luminance、Watermark、Settings等）
- 这些效果调节器会触发项目效果计算，导致调节响应卡顿
- 程序化纹理调整应该是独立的，不应该触发项目效果计算

**根本原因**：
1. [`MobileControls.vue`](demo/src/components/mobile/MobileControls.vue:1) 中的调节器组列表是静态的，没有根据画布模式动态过滤
2. 程序化模式和项目模式共享同一套调节器面板，没有隔离
3. 效果调节器的参数变更会触发项目效果计算，即使在程序化模式下也会执行

#### 解决方案

**实现位置**：
- 移动端：[`demo/src/components/mobile/MobileControls.vue`](demo/src/components/mobile/MobileControls.vue:145)
- 桌面端：[`demo/src/components/desktop/DesktopControls.vue`](demo/src/components/desktop/DesktopControls.vue:145)

**核心思路**：
1. **UI层面**：在控制面板组件中引入画布模式管理器
2. **UI层面**：定义效果调节器组ID列表（需要在程序化模式下禁用的面板）
3. **UI层面**：使用 `computed` 属性根据当前画布模式动态过滤可用的调节器组
4. **UI层面**：程序化模式下只保留必要的面板（contact、inputs、view、save）
5. **UI层面**：移动端和桌面端使用相同的过滤逻辑，确保行为一致
6. **逻辑层面**：修改监听器，在程序化模式下阻止触发效果计算

**代码实现**：

```typescript
// 画布模式管理器
const canvasModeManager = useCanvasModeManager()

// 效果调节器组ID列表（在程序化模式下需要禁用）
const EFFECT_ADJUSTMENT_GROUP_IDS = [
  'crop',           // 裁剪
  'lut',            // LUT调色
  'hsl',            // HSL调整
  'exposure',       // 曝光调整
  'dehaze',         // 去雾
  'clarity',        // 清晰度
  'luminance',      // 亮度分区
  'watermark',      // 水印
  'tileablesettings' // 平铺设置
]

// 根据画布模式过滤可用的调节器组
const groups = computed(() => {
  const currentMode = canvasModeManager.activeModeId.value
  
  // 程序化模式下，禁用效果调节器
  if (currentMode === CANVAS_MODE_IDS.PROCEDURAL) {
    return allGroups.filter(group => !EFFECT_ADJUSTMENT_GROUP_IDS.includes(group.id))
  }
  
  // 其他模式下，显示所有调节器
  return allGroups
})
```

#### 技术细节

**1. 响应式过滤机制**

使用 Vue 的 `computed` 属性实现响应式过滤：
- 当画布模式切换时，`canvasModeManager.activeModeId.value` 变化
- `computed` 自动重新计算可用的调节器组
- UI 自动更新，隐藏被禁用的调节器

**2. 模式隔离**

```
项目模式 (PROJECT)
├── contact
├── inputs
├── crop          ✓ 可用
├── lut           ✓ 可用
├── hsl           ✓ 可用
├── exposure      ✓ 可用
├── dehaze        ✓ 可用
├── clarity       ✓ 可用
├── luminance     ✓ 可用
├── watermark     ✓ 可用
├── tileablesettings ✓ 可用
├── view
└── save

程序化模式 (PROCEDURAL)
├── contact
├── inputs        ✓ 可用（包含程序化纹理面板）
├── crop          ✗ 禁用
├── lut           ✗ 禁用
├── hsl           ✗ 禁用
├── exposure      ✗ 禁用
├── dehaze        ✗ 禁用
├── clarity       ✗ 禁用
├── luminance     ✗ 禁用
├── watermark     ✗ 禁用
├── tileablesettings ✗ 禁用
├── view          ✓ 可用
└── save          ✓ 可用
```

**3. 性能优化**

- 使用 `computed` 而不是 `watch`，避免手动管理依赖
- 使用 `filter` 而不是重新创建数组，保持对象引用稳定
- 只在模式切换时重新计算，不会频繁触发

## 常见问题与解决方案

### Q1: 为什么需要版本号机制？

**问题**：直接在 `getOutput()` 中返回 `currentTextureDataUrl` 不行吗？

**答案**：不行。因为：
1. `currentTextureDataUrl` 是普通变量，不是响应式的
2. Vue 的 computed 只能追踪响应式依赖（ref, reactive）
3. 即使访问了 `currentTextureDataUrl`，Vue 也无法知道它何时变化

**正确做法**：
- 使用 `outputVersion.value++` 触发响应式更新
- 在 `getOutput()` 中访问 `outputVersion.value` 建立依赖关系

### Q2: 为什么不直接让 `currentTextureDataUrl` 成为 ref？

**答案**：可以，但会增加复杂度：
1. 需要在所有访问处使用 `.value`
2. 版本号机制更清晰地表达"状态已更新"的语义
3. 版本号可以用于调试和日志记录

### Q3: 模式切换时数据会丢失吗？

**答案**：取决于模式的实现：
- **项目模式**：数据存储在 IndexedDB，不会丢失
- **程序化模式**：临时数据，切换后会丢失（除非保存为项目）
- **模式实例缓存**：`useCanvasModeManager` 会缓存模式实例，避免重复创建

### Q4: 如何添加新的画布模式？

**步骤**：
1. 在 `demo/src/composables/canvas-mode/modes/` 下创建新模式目录
2. 实现 `CanvasMode` 接口
3. 在 `demo/src/composables/canvas-mode/modes/initialize.ts` 中注册
4. 在 UI 中添加切换入口

**示例**：
```typescript
// modes/paintMode/index.ts
export function createPaintMode(): CanvasMode {
    const isDirty = ref(false)
    const outputVersion = ref(0)
    let currentCanvas: HTMLCanvasElement | null = null
    
    return {
        id: 'paint',
        displayName: '绘制模式',
        persistStrategy: 'confirm',
        isDirty,
        outputVersion,
        
        async onEnter(): Promise<void> {
            // 初始化画布
        },
        
        async onExit(): Promise<void> {
            // 清理资源
        },
        
        getOutput(): CanvasOutput {
            const _version = outputVersion.value
            return {
                displayImage: currentCanvas?.toDataURL() || null,
                overlays: [],
                metadata: { version: _version }
            }
        },
        
        async persist(): Promise<void> {
            // 保存为项目
        }
    }
}
```

## 性能优化建议

### 1. 模式实例缓存

`useCanvasModeManager` 会自动缓存模式实例，避免重复创建：

```typescript
const modeInstanceCache = new Map<string, CanvasMode>()

async function getOrCreateModeInstance(modeId: string): Promise<CanvasMode> {
    const cached = modeInstanceCache.get(modeId)
    if (cached) return cached
    
    const instance = await definition.factory()
    modeInstanceCache.set(modeId, instance)
    return instance
}
```

### 2. 防抖保存

项目模式使用防抖保存，避免频繁写入 IndexedDB：

```typescript
// useProjectState.actions.ts
let saveDebounceTimer: ReturnType<typeof setTimeout> | null = null

export function 防抖保存项目(project: ImageProject): void {
    if (saveDebounceTimer) {
        clearTimeout(saveDebounceTimer)
    }
    
    saveDebounceTimer = setTimeout(async () => {
        await projectFS.saveProject(project)
    }, 保存防抖延迟)  // 默认 500ms
}
```

### 3. 竞态条件处理

项目切换时使用竞态条件检查，避免加载过期数据：

```typescript
export async function 切换项目(id: string): Promise<void> {
    activeProjectId.value = id
    const blob = await projectFS.loadAsset(originalKey)
    
    // 竞态条件检查
    if (activeProjectId.value !== id) return
    
    const dataUrl = await blobToDataURL(blob)
    
    // 再次检查
    if (activeProjectId.value !== id) return
    
    activeOriginalDataUrl.value = dataUrl
}
```
